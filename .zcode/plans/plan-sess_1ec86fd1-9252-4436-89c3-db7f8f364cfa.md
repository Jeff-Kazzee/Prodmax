# Prodmax — an AI-native, originally branded Linear/Notion alternative

Build a production-ready, multi-user project-and-docs workspace ("Prodmax") in the empty repo at `dev/projects/Prodmax`, orchestrated through four phases exactly as requested: Research → UX Planning → Build → Verify. All branding, copy, code, and design are original; Linear/Notion are studied as competitive reference only. Weaknesses found in research become explicit product improvements (e.g., Notion's scale slowness → local-first fast path; Linear's restrictive free tier / opaque AI pricing → unlimited local AI engine with transparent usage stats).

## Locked decisions (from owner)

| Decision | Choice |
|---|---|
| Brand | **Prodmax** (directory name is the product name) |
| Framework | **Astro 5** (SSR + Node adapter) with the app as a full React island (React Router inside one catch-all route); Astro middleware = auth/API edge |
| UI system | **Tailwind + shadcn/ui** (required by dither-kit/icons0), **dither-kit** for retro dithered charts/avatars, **canvasui** for signature visual effects, **icons0** (Iconify via shadcn CLI) for icons, **shieldcn** SVG badges/charts for README + in-app status shields |
| Database | **SQLite** via Drizzle ORM + better-sqlite3, file-based, zero external services |
| Auth | Email+password, HTTP-only cookie sessions, own middleware (no experimental APIs) |
| AI | **Keyless-first**: provider-agnostic AI layer with a deterministic local engine so every AI feature fully works offline; LLM providers plug in via `.env` later |
| Realtime | **SSE live sync + presence** (~1s propagation, presence indicators, activity feed, optimistic UI; no CRDT co-editing) |
| Testing | Vitest + Testing Library (unit/integration), Playwright (E2E), chrome-devtools MCP + browser-use (agent-driven live UI verification), axe (a11y) |

## Phase 1 — Research (no app code; planning docs only)

Launch parallel research agents (general-purpose, web-enabled), each writing a section of `planning/research/`:
- **R1 Linear deep-dive**: full feature surface (issues, cycles, projects, triage, views/filters, keyboard UX, command palette, integrations, API model, pricing/limits, Linear Agent capabilities), praised features, complaints (free-tier limits, AI pricing opacity, mobile).
- **R2 Notion deep-dive**: block model, page tree, database types/properties/relations/rollups, templates, search, API, complaints (slowness at scale, database recomputation, block bloat, weak mobile).
- **R3 AI-native patterns + alternatives**: how Height/Attio/Shortcut/Linear embed AI; which AI workflows users actually value (triage, dedup, NL→query, summaries, drafting); edge cases and failure modes.

Consolidation step (single agent): merge into three canonical docs that gate all later phases:
1. `planning/research/feature-matrix.md` — every feature: parity tier (must/should/stretch), source rationale, and the Prodmax improvement over the incumbent's weakness.
2. `planning/architecture.md` — data model (workspaces, users, issues, states, labels, cycles, projects, page blocks, views, notifications, activity), API surface, SSE event bus, AI provider abstraction, module boundaries.
3. `planning/qa/acceptance-tests.md` — numbered acceptance tests (happy paths, permissions, isolation, edge cases) with exact manual steps + automated mappings; this is the Phase 4 exit gate.

## Phase 2 — UX & interaction design (still no app code)

Dedicated design agents walk every user journey end-to-end and write `planning/design/`:
- `ux-spec.md` — screen-by-screen flows: first-run/onboarding, login, workspace setup, issue CRUD (list/board/table), triage inbox, cycle planning, doc editing, AI interactions (every prompt surface, loading/success/failure states), search, notifications, settings/admin. Every interaction specified: keyboard shortcuts, command palette behavior, focus management, optimistic updates + SSE reconciliation, empty/loading/error states, and **intentional animations** (durations, easings, what animates and why — dither/canvas effects used purposefully as brand signature, never noise).
- `design-system.md` — Prodmax brand: palette, typography scale, spacing, dark/light themes, component inventory mapped to shadcn/dither-kit/canvasui, motion tokens, voice/copy guide (original microcopy throughout).

## Phase 3 — Build (module ownership; fresh agent per module)

First write `planning/plans/build-prodmax.md` (SOP-01 plan doc, this plan expanded with research findings) and `AGENTS.md` (project validation commands: `npm run check` / `npm test` / `npm run e2e` / `npm run build`). Then scaffold once (M0), then one narrowly-scoped agent per module with explicit file ownership to prevent overlapping edits:

| Module | Owns (exclusive) | Key deliverables |
|---|---|---|
| M0 Foundation | scaffold, config, tsconfig, tailwind, shadcn, drizzle setup | App boots, CI-equivalent scripts pass |
| M1 Data & API core | `src/db/**`, `src/pages/api/**` | Full schema + migrations + seed; REST endpoints w/ zod validation |
| M2 App shell | island entry, router, layout, sidebar, command palette, hotkeys, theming, toasts | Navigation + Cmd+K + shortcut system per ux-spec |
| M3 Issues engine | issue views, board/list/table, filters, saved views, bulk ops, triage | The Linear-parity core |
| M4 Projects & cycles | projects, milestones, cycle planning/scope | Progress, burndown-ready data |
| M5 Docs engine | block editor, page tree, templates, doc-embedded issue views | The Notion-parity core |
| M6 AI layer | `src/lib/ai/**` | Deterministic engine: triage, dedup, NL→filter, summaries, drafting, "ask workspace"; provider interface |
| M7 Insights | analytics pages | Velocity, burnup, created-vs-completed, breakdowns via dither-kit |
| M8 Realtime | SSE bus, presence, activity, notifications, inbox | Live sync + presence + inbox |
| M9 Integrations | API keys, webhooks, CSV import/export | Public REST surface + event webhooks |
| M10 Settings & admin | members, roles, invites, workspace settings | Permission enforcement UI |

Rules: shared constraints doc (naming, zod error shape, SSE event names, drizzle conventions) written by M0/M1 and binding on all; each module lands with its own vitest tests green before the next starts; integration checkpoint after every module (run full suite + manual smoke of adjacent flows). Real functionality only — no placeholder controls, no disconnected demos.

## Phase 4 — Verify (adversarial loop until green)

- Run the real app (`npm run build && npm run preview` + dev mode) and drive it with browser agents (chrome-devtools MCP + browser-use).
- Parallel dedicated agents: **security/adversarial** (authz between workspaces/roles, CSRF, injection, XSS via editor content, API key abuse), **data isolation** (multi-user, multi-org cross-access attempts), **a11y** (axe + keyboard-only + screen-reader passes), **visual** (breakpoints, dark/light, animation correctness), **edge cases** (empty states, offline SSE reconnect, concurrent edits, unicode/long input, huge boards pagination).
- Every defect logged in `planning/qa/defect-log.md` (severity, repro, fix commit, retest result). Fix → retest → repeat.
- **Exit criteria**: every acceptance test in `planning/qa/acceptance-tests.md` passes; `npm run check`, `npm test`, `npm run e2e`, `npm run build` all clean; zero known material defects; README with shieldcn badges + full setup/run instructions.

## Communication rule

Proceed autonomously through all phases. Ask the owner only when blocked on missing credentials, an irreversible external action, or a consequential product decision (per your instruction). Progress reported per phase with the canonical docs as artifacts.
