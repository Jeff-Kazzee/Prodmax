## What is open, in the order it matters

**T-023, workflow state writes corrupt project progress.** `PATCH
/api/states/:id` can change a state's `category`, and `DELETE` reassigns every
issue in the state, both with no event and no repair. Every project counter in
the system goes silently wrong the moment an admin recategorizes a state. This
undercuts the guarantee T-005 just bought, so it outranks new features.

**T-024, consumer policy and version monotonicity.** Three design questions that
bind T-016 and M9. Every consumer is currently mandatory, synchronous, and
inside the user's transaction, which is right for a counter and wrong for a
webhook dispatcher. Undo moves `version` backwards. `GET /api/cycles` writes.
Cheaper to answer now than to retrofit.

**T-006, projects and cycles UI.** The next feature ticket. Its API is done and
the §3.5 route for listing cycles is now `GET /api/cycles?wsId=&teamId=`, not
the team-scoped path the old spec named. Check the amended §3.5.

Also open and unowned: dropping the dead `teams.next_cycle_number` column needs
a migration ticket. Whether archived issues count toward progress is a §2.4 gap
and a product decision, not an engineering one. The e2e suite is not idempotent
against an accumulated `data/prodmax.db`.

## What went wrong last round, and what now stops it

Five times in one session an artifact contradicted a summary about it. Once by a
swarm, twice by subagents, twice by me. Every one was caught by opening the
artifact, never by reading the report.

| What was claimed | What was true | Now prevented by |
|---|---|---|
| T-005 done, four gates green | Five blocking defects | CI, and `/interrogate` before the gates on swarm work |
| Phases 3 to 6, all four gates green | One test file failing | `scripts/gates.mjs` verdict block |
| Cycle batching kept working | It silently dropped the `version` bump | The agent surfaced it, and a test now locks it |
| Phase 5 spec: repair then increment | Double-counts the current mutation | Caught by architect before code |
| All eleven phases landed | Phase 7 never assigned | Cross-model trail audit, now mandatory |

**The mechanism behind most of them.** `npm test 2>&1 | tail -5` exits 0 no
matter what vitest did, because a shell pipeline returns the status of its last
command. Every "all four gates green" report that turned out false used that
shape. So did my own runs. Vitest also prints test files and tests on separate
lines, so a file can fail with zero failing assertions and the count a reader
scans for still looks clean.

**What now exists because of it.**

- `scripts/gates.mjs` runs all four gates, keeps every exit code, prints a
  verdict block last, and exits non-zero on any failure. It prints both the file
  count and the test count. Run it and paste the block verbatim.
- `.github/workflows/gates.yml` runs the same runner on every PR into `dev`.
  This is the one that matters, because it takes every summary out of the trust
  path. A red check cannot be talked around. **It is currently inert.** The
  first run on PR 9 failed in three seconds with "the job was not started
  because your account is locked due to a billing issue". The workflow is
  correct and untested. Until the billing block clears, the gate runner is the
  only enforcement and it still depends on someone choosing to run it.
- `CLAUDE.md` carries the reporting rules, including that a falsification must
  assert its own anchor. Proving a test catches a break is worthless when the
  edit silently matched nothing, which happened here once.

**The habit worth keeping, since no script enforces it.** Break the thing,
confirm the test fails, put it back. Every fix that shipped this round was
falsified that way: the guest close returned 200 on the baseline, the ordering
repro failed with `expected +0 to be 100`, the rollback proof failed three of
four when the flush moved past commit, the version test failed with `expected 1
to be 2`, and the parenting guard removed returned 201 and stored a cross-tenant
reference silently.
