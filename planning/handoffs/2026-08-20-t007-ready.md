## What changed about how you report a gate

**CI can read its own counts now.** T-027 fixed the parser, so a CI verdict
block prints real numbers rather than `counts unparsed`. If you see that marker
again, the run also exits 2 and prints an `EVIDENCE MISSING` block with the tail
it could not parse. That is a distinct failure from a gate failing, which is
exit 1. Do not conflate them.

The rest of `CLAUDE.md`'s reporting rules stand unchanged, and they are not
advice. Run `node scripts/gates.mjs` whole, never through a pipe, and paste the
verdict block verbatim.

CI browser downloads are cached on the lockfile and the timeout is 30 minutes,
so a cold-install cancellation should no longer masquerade as a red check. A
cold run is about 13 minutes, a warm one under 2.

## Review discipline, carried forward

Four independent reviewers ran against T-006 at a frozen commit. What they found
is worth knowing before you write tests here, because most of it was invisible
to ordinary review.

**Two of the assertions could not fail.** One asserted no PATCH was sent in a
test that clicked nothing. Another named an off-by-one that its own clamp made
unfalsifiable. Both read as rigorous. Both were theater. The reviewer that
caught them did it by mutating the source and re-running, not by reading.

**So mutate, do not just read.** After writing a guard, break the thing it
guards and confirm that the specific new assertion fails with the message you
expected. Assert the anchor string was present before replacing it, so a no-op
edit cannot masquerade as proof. Every ticket in this session records those
messages in its work log, and that record is the point.

**Watch for fixtures that agree with the wrong implementation.** A backlog
fixture returned only unscoped issues, so deleting the client-side filter it
was meant to pin changed nothing. Choose numbers a wrong implementation cannot
also produce: the S-15 progress fixture reads 62 from the cache, 100 from a
scan, 53 from the points pair and 39 from the issue pair, so only one of the
four is reachable by accident.

**Run the island suites shuffled before you trust them.**

```bash
npx vitest run tests/island/features/ --sequence.shuffle.tests --sequence.seed=2
```

The router in `src/island/app.tsx` is module state built once, so a test can
inherit the previous one's location, and an open Radix modal marks the rest of
the document `aria-hidden`, which makes the whole shell invisible to role
queries. A cycles test that failed only under seed 2 turned out to be reporting
a real product bug, T-033, not a harness quirk. Chase order-dependence rather
than papering over it.
